# Historical source references

These files are redacted, deliberately disabled source for review only. They are **not installation procedures, executable tools, approved checkpoints, or proof of recovery**. Their `.py.txt` extension and unconditional exception prevent accidental execution; they contain undefined placeholders. Do not turn placeholders into guessed values or infer that their logic is safe for a different installation.

- `checkpoint_writer.py.txt`: a later one-off checkpoint writer. It shows checks on the prepared action, identity, archive, prior managed pair, backup, clock and witness age, and its atomic write. The private paths, identifiers, target and prestate, peer fingerprint, hashes, prepared revision and credential expiry are removed. The approval/readiness fields are placeholders for independently supported operator attestations. This script did not authenticate its witness or establish physical/recovery readiness. Original source SHA-256: `de60dce94d0df2ba2e59b5743f768b84bf24ec8cd9a93cf0e15d87cc5c219ffb`.
- `historical_authorize_install.py.txt`: earlier target-specific checkpoint and certificate-extension verifier. Target, identity, paths, hashes, prestate, revisions, expiry and witness bindings are removed. It depended on particular older integration bytes and an independently staged witness; this is not a general validation or an authorization. Original SHA-256: `83466bb0cb3410b2bd6bc616a0a45c8af5dcb51228291863d40169126fd895b0`.
- `historical_cross_build.py.txt`: older isolated cross-link orchestration, retained to show build isolation and checks. Host paths, distro and container name are removed. It uses historical workspace inputs, not the current published source tree; use the current `firmware-source/README-SOURCE.txt` and transforms to understand the released application. This is not a reproducible-build claim or a ready-to-run builder. Original SHA-256: `46bd24c08c1280a15e05ba68641a93771ed1dfc299530232efbdadc7c1eb987c`.

Current deployment and recovery logic is in `custom_components/intercom_m3_poc/manager_deployment.py` and the paired firmware scripts. A public general checkpoint creator and fully verified installation, managed-transfer and recovery procedure remain unavailable. Operator claims such as approval, boot-clock readiness and recovery readiness require independent evidence; these references do not generate it.

Other inventoried material omitted: private credential transfer and witness scripts contain installation-bound secrets and household state; per-run backups and their file inventories contain private data; old RAM install/rollback and packaging helpers depend on earlier layouts and artifacts, and are not the current release's installer. Their inclusion as an unreviewed collection would risk suggesting obsolete paths are current. The current paired rollback logic and exact source transforms are included elsewhere in this tree. Vendor SDKs, binary libraries, models and stock backups remain excluded because distribution rights and provenance are not established.
